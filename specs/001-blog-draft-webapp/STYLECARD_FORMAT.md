# 文体カード (.md) ファイルフォーマット

## 概要

`StyleCard:FilePath` で指定される `.md` ファイルは、ブログ下書き生成時に LLM に与えるシステムプロンプト（執筆ガイド）として使用されます。複数セクションを含む Markdown フォーマットで、LLM に対する指示をプレーンテキストで記述します。

---

## 基本的なファイル構成

文体カードファイルは、以下の要素で構成されます：

```markdown
# [トップレベルセクション: 執筆方針、トーン、ガイドラインなど]

## [サブセクション: 具体的なルール]

- [リスト形式での指示]
- [複数の指示項目]

### [より細粒度のセクション]

段落形式での説明や例示

---

## [別のトピック]

...
```

---

## 推奨セクション構成

以下は、効果的な文体カードの構成例です。すべてのセクションが必須ではなく、プロジェクトのニーズに合わせてカスタマイズしてください。

### 1. 基本方針（必須）

**目的**: LLM に対して、ブログ記事全体のトーンと目的を明確に伝えます。

```markdown
# 執筆方針

あなたはテックブログの執筆アシスタントです。
読者に寄り添い、実践的で分かりやすい記事を生成してください。
```

### 2. ターゲット読者

**目的**: 記事の難易度、用語選択、例示レベルを適切に設定します。

```markdown
## ターゲット読者

- 初～中級の開発者
- Azure クラウドサービスの基本知識がある
- 実装例を求めている
```

### 3. 記事の構成テンプレート

**目的**: 生成される記事の章立てやセクション構成を指定します。

```markdown
## 記事の構成

以下の順序で記事を構成してください：

1. **導入** - 記事のテーマと解決する課題を 1～2 段落で説明
2. **背景** - なぜこのテーマが重要か、ユースケースを説明
3. **前提条件** - 必要なツール、知識、環境を箇条書き
4. **実装ステップ** - 段階的な手順をコード例とともに説明
5. **ベストプラクティス** - 注意すべき点、アンチパターン
6. **まとめ** - 重要なポイントの要約と次のステップ
```

### 4. トーン・スタイル

**目的**: 文章の雰囲気、敬語レベル、表現方法を指定します。

```markdown
## トーン・スタイル

- 敬語: ビジネス的だが親しみやすい（です・ます調）
- 表現: 「〜できます」「〜の方法があります」など肯定的で建設的
- 図表: コンセプトが複雑な場合は ASCII アート またはテキスト図で表現
- コード: C# の最新ベストプラクティスに従う
```

### 5. コード例に関するルール

**目的**: コード例の品質、形式、スタイルを統一します。

```markdown
## コード例ルール

- 言語: C# 12 以上、.NET 10 互換
- スタイル: Microsoft naming conventions に従う（PascalCase for classes、camelCase for variables）
- コメント: 複雑なロジックのみ日本語でコメント
- エラーハンドリング: 例外処理、null checks を明示的に記載
- 実装性: 実際に動作するコード例を示す（パスワードなど秘匿情報は含めない）
```

### 6. 参考資料・リンク

**目的**: LLM が参考にするべき公式ドキュメントやベストプラクティスガイドへのリファレンス。

```markdown
## 参考資料

公式ドキュメント:
- [Azure Functions documentation](https://docs.microsoft.com/azure/azure-functions/)
- [Durable Functions overview](https://docs.microsoft.com/azure/azure-functions/durable/)

関連技術:
- Azure Service Bus（非同期メッセージング）
- Azure Cosmos DB（状態管理）
```

### 7. 禁止事項・注意

**目的**: 生成時に避けるべき表現、技術、内容を明記します。

```markdown
## 禁止事項

- 古い .NET Framework 情報は含めない
- CLI コマンドは Windows PowerShell / Bash 両対応を示す
- 非推奨 API は使用しない
- パスワード、API キー、シークレット情報を例に含めない
```

## 完全な例

以下は、実際の文体カードの例です：

```markdown
# 執筆方針

あなたはエンタープライズ向けの Azure・C# 技術ブログの執筆アシスタントです。
読者に寄り添い、実践的で再現可能な記事を生成してください。
記事は日本語で記述し、技術用語は英語のまま（または最初に日本語訳を併記）。

## ターゲット読者

- 中級以上の C# / .NET 開発者
- Azure 基本サービス（App Service、Functions、Storage）の実装経験がある
- 実装例とベストプラクティスを求めている

## 記事の構成

1. **導入** - テーマと解決する課題を簡潔に（2～3 段落）
2. **なぜ重要か** - ユースケース、パフォーマンス改善効果など
3. **前提条件** - 必要なツール、NuGet パッケージ、環境設定
4. **実装ステップ** - コード例とともに段階的に説明
5. **実装例** - 完全に動作するサンプルコード
6. **ベストプラクティス** - 本番環境で気をつけるポイント
7. **トラブルシューティング** - よくあるエラーと対処法
8. **まとめ** - 重要なポイント、次のステップ

## トーン・スタイル

- 敬語: ビジネス的だが親しみやすい（です・ます調）
- 表現: 「〜できます」「推奨します」など肯定的で建設的
- 図表: 複雑な概念は ASCII アート で表現
- 見出し: H1～H4 を使用（H5 以上は不要）

## コード例ルール

- 言語: C# 12 以上、.NET 10 対応
- スタイル: Microsoft naming conventions
- コメント: 複雑なロジックのみ日本語で簡潔に
- エラーハンドリング: 明示的に記載
- 実装性: 実際に動作するコード例のみ

## 禁止事項

- 非推奨 API、古い .NET Framework 情報
- パスワード、シークレット情報を例に含める
- 実装不可能なコード例
```

## フォーマット要件

| 要件 | 説明 |
|-----|------|
| **ファイル形式** | UTF-8 エンコーディング |
| **最大サイズ** | 推奨 10,000 字以内（LLM コンテキスト節約のため） |
| **改行** | Unix スタイル（LF）推奨 |
| **セクション** | Markdown 見出し（#、##、###）で構造化 |
| **リスト** | `-` または `*` を使用（`1.` は不要） |
| **コードブロック** | ` ``` ` でラップ、言語指定あり |
| **特殊文字** | 機微情報（パスワード、キー）は含めない |

## 使用方法

### 開発環境での設定

User Secrets でファイルパスを指定:

```powershell
dotnet user-secrets set "StyleCard:FilePath" "C:\secrets\stylecard.md"
```

ファイルパスは絶対パスまたは相対パス（Application Base Path からの相対）で指定してください。

### 本番環境での設定

Azure Key Vault を使用:

```powershell
# Key Vault に秘密として保存
az keyvault secret set --vault-name myKeyVault --name StyleCardFilePath --file C:\secrets\stylecard.md

# アプリケーション設定で参照
az webapp config appsettings set --resource-group myRG --name myApp --settings "StyleCard__FilePath=@Microsoft.KeyVault(SecretUri=https://myKeyVault.vault.azure.net/secrets/StyleCardFilePath/)"
```

## トラブルシューティング

### ファイルが見つからないエラー

```
FileNotFoundException: StyleCard file not found: C:\secrets\stylecard.md
```

**原因**: ファイルパスが不正、またはファイルが存在しない。

**解決策**:
1. ファイルパスの存在を確認: `Test-Path "C:\secrets\stylecard.md"`
2. 絶対パスを使用してください。
3. アクセス権限を確認してください。

### ファイルが空のエラー

```
InvalidOperationException: StyleCard file is empty: C:\secrets\stylecard.md
```

**原因**: ファイルが存在するが内容が空。

**解決策**:
1. ファイルに内容が記述されていることを確認。
2. 文体カード例を参考に記述してください。

### FilePath と Content が両方指定されている場合

**動作**: FilePath が優先され、Content の値は上書きされます。
